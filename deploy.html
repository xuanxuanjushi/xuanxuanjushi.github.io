Deploy · GitHub Pages

把网页应用送上 GitHub

选择本地文件夹（或站内示例）→ 填写目标仓库 → 一次提交推送，并自动开启 GitHub Pages。 全流程在你的浏览器里直连 GitHub API，没有中间服务器，代码不经过任何第三方。

1

连接 GitHub

已连接
建议用 classic token，勾选 repo 权限即可。 在 GitHub → Settings → Developer settings → Personal access tokens 生成。 令牌只存在当前标签页的 sessionStorage（关页即失效），仅发送到 api.github.com。
2

选择应用文件

拖入应用文件夹 也可以点击这里选择文件夹（自动忽略 node_modules、.git 等）
尚未选择文件。入口文件需要命名为 index.html，否则 Pages 打开是 404。
3

目标仓库与选项

不存在会自动创建。
Pages 默认发布该分支根目录。
一个仓库放多个应用时填写，例如 apps/pomodoro。
首次部署约需 30～90 秒（Pages 构建时间）。

需要知道的事

          

            
    
              
  • 令牌安全：存在当前标签页的 sessionStorage，不写日志、不进 URL。公用电脑用完请点「断开并清除令牌」。
    • 
              
  • 单文件上限：单个文件超过 25 MB 会被跳过，图片建议先压缩。
    • 
              
  • 构建等待：Pages 首次构建通常 30～60 秒，日志会轮询状态直到 built。
    • 
              
  • 更新而非覆盖：再次部署同一仓库为增量提交，旧文件保留；要删除文件请直接在 GitHub 上操作。
    • 
              
  • 回滚方式：仓库的每次部署都是一个 commit，git revert 或 GitHub 上 revert 即可。
    • 
              
  • 私有仓库：免费账号的私有仓库不能开 Pages，日志会给出提示但不阻断推送。
